# 検索式自動調整の再評価: 所見（#106 改定後）

実施 2026-09-14。計画は [再評価計画](query-optimization-rerun-plan.md)、改定前の所見は [所見](query-optimization-bench-findings.md)、再現手順は [experiments/query-optimization-bench/README.md](../experiments/query-optimization-bench/README.md)。

**4 ケース（開発 3・確認 1）・2 分割・各 3 ドラフトの後ろ向き探索的評価**であり、新しいレビューでの性能や専門家の検索への非劣性は示さない。数値は現在の PubMed に作成日上限を適用して測った。

## 結論

**改定後の自動調整は「未知の適格研究を落とす削除を採用しない」ようになった。一方で、件数はほとんど減らせていない。**

- 旧版は凍結 C0 48 組のうち 20 組で held-out を落とす変更を採用した（有害採用 32 件）。新版の有害採用は 0 件
- 初期式の生成は、新版では 36 枠すべてが PubMed で実行でき（構文エラー 0）、旧版のその場生成は 24 回中 6 回が実行できない式だった（ほかに 3 回は Gemini の HTTP 429 で未取得）
- その代わり、新版は件数を目標（2,000 件）へほとんど近づけていない。旧版が件数を削れた局面の多くは、held-out を落とす削除だった
- 外側の確認と模擬レビュアーによる再調整で、取りこぼしを最終式へ回収できたのは 48 run 中 5 run だった

事前に固定した判定基準の結果:

| 基準 | 結果 | 要点 |
|---|---|---|
| S1 安全 | **満たす** | 新版の有害採用 0 件（全 48 run を採点）。旧版が有害採用した 20 組で、新版は採用 2 件（いずれも有害でない）、保留 22 件（すべて失う集合を実測して正の件数）、却下 19 件 |
| S2 劣化なし | **満たさない（2 組）** | 新版の最終式だけが落とした研究がある組が 3 組。1 組は LLM 提案のぶれ、2 組は削除と追加をまとめた候補を新版が安全側で丸ごと保留したため（調整ロジック起因）。その 2 組でも held-out の捕捉数は新版が上回る（20 対 13、19 対 14） |
| S3 通しで良くなった | **満たす（事後に決めた扱い）** | 4 ケースすべてで新版の中央値が旧版以上。旧版の初期式が実行できなかった run を再現率 0 と数えた（結果を見た後に利用者が決めた扱い。事前の規則では失敗のある 3 ケースは判定不能） |
| S4 取りこぼしを回収できる | **満たす** | 模擬レビュアーの再調整だけで回収した run が、開発用 3 ケースと確認用 1 ケースのそれぞれにある |
| S5 誤った安心を出さない | 0/9 | 条件達成なのに held-out を取りこぼした 9 run のすべてで、外側の確認が候補を 4〜5 件示した（候補 0 件で「確認済み」になった run は無い） |

| R1 | 1 / 1 | 0 / 0 | 1.000 / 1.000 | 745 / 745 |
| R2 | 0 / 40 | 0 / 23 | 0.963 / 0.815 | 15,794 / 4,202 |
| R3 | 2 / 17 | 0 / 1 | 0.933 / 0.900 | 2,121 / 1,518 |
| c1（確認） | 1 / 10 | 0 / 8 | 0.905 / 0.667 | 2,963 / 894 |
| 計 | 4 / 68 | 0 / 32 | — | — |

- **R2** は改定前の所見で危険な削除が見つかったケースで、差が最も大きい。旧版は 12 組中 11 組で `ballard 1986`・`burditt 1968`・`miki 1969`・`teuscher 1988` などを落とす削除を採用し、5 反復を使い切って止まった。新版は採用 0 件で、削除候補を差集合の実測で保留した（保留 13 件）
- **c1（確認用）** でも同じ構造が出た。旧版は食塩関連の MeSH（`Diet, Sodium-Restricted`・`Sodium, Dietary` 等）を削る変更を採用し、`arzilli 1986`・`kawasaki 1998`・`toft 2020` などを落とした（8 組）。開発用ケースだけでなく、確認用ケースでも削除の保留が効いた
- **R1** は初期式の段階でほぼ全件を捕捉しており、差は出なかった
- **R3** は旧版の有害採用が 1 件だけで、旧版は held-out をあまり落とさずに件数を削れた。R3 のパイロットで見えた「旧版のほうが件数を絞れる」局面はこのケースに集中している

**新版が落とした研究（S2）**

| 組 | 新版だけが落とした | 新版だけが捕捉 | 原因 |
|---|---|---|---|
| R1 `seeded-draft12-s20260915` | gaskins 2015 | bloom 2020 | LLM 提案のぶれ。旧版は `mindfulness`/`meditation`/`yoga` を、新版は `mindful*` を足した。模擬レビュアーの再調整で gaskins 2015 も回収し、最終式は新版 14・旧版 13 |
| c1 `criteria-only-draft13` s20260912 | allaert 2013 | arzilli 1986 ほか 7 研究 | 調整ロジック。旧版は「食塩 MeSH の削除＋代替塩の語の追加」を 1 候補として採用し、allaert 2013 を得て 8 研究を失った。新版は同じ種類の候補を、捕捉済みシードを失う・失う集合 652 件として保留・却下した |
| c1 `seeded-draft11` s20260912 | allaert 2013 | arzilli 1986 ほか 5 研究 | 同上（失う集合 2,650 件で保留） |

後の 2 組は、候補を丸ごと判定する設計の帰結である。有益な追加が有害な削除と同じ候補に入ると、追加ごと捨てる。

### 層 A: 適格基準からの通し比較（criteria-only）

| ケース | 新版 C1 再現率の中央値（n） | 旧版（自前 C0）の中央値: 失敗を 0 と数える / 失敗を除く | 旧版の失敗（構文 / 一時） | 件数の中央値（新 / 旧） |
|---|---|---|---|---|
| R1 | 1.000（6） | 1.000 / 1.000 | 0 / 0 | 745 / 211 |
| R2 | 0.963（6） | 0.741 / 0.778 | 1 / 0 | 14,607 / 4,135 |
| R3 | 0.900（6） | 0.800 / 0.833 | 2 / 0 | 1,934 / 1,518 |
| c1 | 0.714（6） | 0.000 / 算出不可（完了 0 件） | 3 / 3（Gemini 429 で未取得） | 1,431 / 欠測 |

- **初期式の実行可能性が最大の差だった。** 旧版の生成器が作った式のうち、R2 の 1 件は引用符の無い `Diabetic Retinopathy, Proliferative[Mesh]` を PubMed が末尾の `Proliferative` だけで照合して失敗した（#132 で直したバグと同じ）。c1 の分割 s20260912 の 3 件はいずれも `phrase not found "Substitutes"` だった。R3 の 2 件は in-band エラー。新版の生成器（36 枠）は全件が凍結前の実測を通った
- c1 の旧版は 6 回とも完了しなかった。分割 s20260912 の 3 回は初期式が実行できず（構文エラー）、分割 s20260915 の 3 回は旧版の初期式生成の LLM 呼び出しが Gemini の HTTP 429 で失敗した。429 は 3 分おきに 2 回取り直しても解消しなかったため「未取得」とし、失敗（再現率 0）には数えていない
- 新版の C1 は、R1〜R3 のすべてで C0 と同じ中央値だった。層 A の差は、初期式の生成と、旧版が採用した有害な削除から来ている
- 旧版の件数の中央値が小さいのは、有害な削除で件数を削ったことと、自前の C0 が小さかったことによる

## 解釈と限界

- **件数の目標にはほとんど届いていない。** 新版の C1 件数の中央値は R2 で約 1.6 万件、c1 で約 3 千件。削除を実測で止めるだけでは件数は減らない。件数を減らしつつ held-out を守る手段（削除と追加の分割、フィルタの提案など）は未解決
- S3 の「失敗を再現率 0 と数える」扱いは結果を見た後に決めた。事前の規則のままなら R2・R3・c1 は判定不能で、S3 は判定できなかった
- 確認用ケースは 1 件だけで、開発用ケースで見えた構造（削除の保留が効く）が一般化するとまでは言えない
- 模擬レビュアーは gold に無い適格研究を exclude と答えるので、実際の人より回収が少なく出うる
- 旧版はパッチを当てた再現で、当時のハーネスそのものではない。旧版の通信層（長い式を GET で送る）は改定前のままだが、今回 HTTP 414 は出ていない
- 入力が完成レビューの Methods であること、LLM の学習混入、現在の索引を使うことは、改定前の評価と同じく残る

## 次に検討すること

1. **削除と追加をまとめた候補を分けて判定する。** c1 の 2 組は、追加だけを採用していれば新版がさらに allaert 2013 を得ていた
2. **件数を減らす手段。** 新版は安全になったが、R2 のように上限の 8 倍の式が残る。held-out を落とさない絞り込み（研究デザインのフィルタ、固有寄与の小さい語の削除候補の見せ方）を、差集合の実測とセットで検討する
3. **include 後に捕捉できなかった 3 run。** シードを保護するだけでなく、include した文献を捕捉する語を探す手順が要る
